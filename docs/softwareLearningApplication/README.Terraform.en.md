## What is Terraform?

**Terraform** is an **Infrastructure as Code (IaC)** tool by HashiCorp that allows you to define, provision, and manage cloud infrastructure using **declarative configuration files** written in **HCL (HashiCorp Configuration Language)**.

Instead of manually creating resources through the AWS console or CLI, Terraform lets you:

- **Define** infrastructure as code (versioned, reviewable, reusable)
- **Plan** changes before applying them (see what will be created/modified/destroyed)
- **Apply** changes automatically and consistently
- **Destroy** all infrastructure cleanly when it's no longer needed
- **Maintain state** of the infrastructure in a state file (`terraform.tfstate`)

| Characteristic | Detail |
|----------------|--------|
| **Language** | HCL (HashiCorp Configuration Language) |
| **Model** | Declarative (you describe *what* you want, Terraform calculates *how* to do it) |
| **State** | Local file (`terraform.tfstate`) or remote (S3 + DynamoDB) |
| **Providers** | AWS, Azure, GCP, Kubernetes, 300+ providers |
| **Versioning** | Each module/resource has its own version |
| **Planning** | `terraform plan` shows the change graph before execution |

## Why Terraform in this project?

This educational project uses Terraform with **two main objectives**:

1. **Learn IaC**: Document how to deploy the infrastructure of a .NET project in AWS using code, not manual clicks.
2. **Local emulation with MiniStack**: Terraform can run **against MiniStack** (the AWS emulator at `localhost:4566`), enabling `terraform plan` and `terraform apply` **without needing an AWS account or costs**.

> **Key design:** The Terraform code is ready to work in **two modes** — local emulation (against MiniStack) and real AWS — without changing a single line of HCL code. Only the variables file (`.tfvars`) changes.

### Benefits of This Approach

| Aspect | Benefit |
|---------|---------|
| **No cost** | Practice `terraform plan` and `terraform apply` without paying anything |
| **Safety** | You don't touch real AWS unless you explicitly decide to |
| **Reproducibility** | Any developer can spin up the same infrastructure |
| **Versioning** | HCL code lives in git with full change history |
| **Learning** | Understand how EKS, ECR, and VPC are deployed in real AWS |

## Terraform File Structure

The `deploy/IaC/` folder contains all Terraform code:

```
deploy/IaC/
├── main.tf                          # Providers + module orchestration
├── variables.tf                     # All parameterized variables
├── outputs.tf                       # Useful output values after apply
├── versions.tf                      # Terraform/provider versions + backend
├── terraform.tfvars.example         # Example values (copy to terraform.tfvars)
├── terraform.minstack.tfvars.example # Values for MiniStack emulation
├── terraform.tfstate                # Local state (generated by terraform apply)
├── terraform.tfstate.backup         # Backup of previous state
├── .terraform.lock.hcl              # Provider version lock
└── modules/
    ├── vpc/
    │   ├── main.tf                  # VPC, subnets, NAT, Internet Gateway, Flow Logs
    │   ├── variables.tf             # Module-specific variables
    │   ├── outputs.tf               # vpc_id, subnet_ids
    │   └── versions.tf
    ├── ecr/
    │   ├── main.tf                  # ECR repositories + lifecycle policy + scanning
    │   ├── variables.tf
    │   ├── outputs.tf               # repository_names, repository_urls, docker_tags
    │   └── versions.tf
    └── eks/
        ├── main.tf                  # EKS cluster, node group, add-ons, OIDC
        ├── variables.tf
        ├── outputs.tf               # cluster_name, endpoint, kubeconfig_command, OIDC
        └── versions.tf
```

### Main File: `main.tf`

The `main.tf` is the entry point. It defines:

1. **The AWS provider** with conditional configuration (point to MiniStack or real AWS).
2. **Three modules** that communicate with each other:
   - `vpc` → provides `vpc_id` and `subnet_ids` to the `eks` module
   - `ecr` → creates image repositories
   - `eks` → creates the EKS cluster using the VPC from the `vpc` module

## AWS Provider

The **AWS provider** is the fundamental block that connects Terraform with AWS services. Defined in `main.tf`:

```hcl
provider "aws" {
  region                      = var.region
  access_key                  = var.aws_access_key
  secret_key                  = var.aws_secret_key
  skip_credentials_validation = var.aws_skip_credentials_validation
  skip_requesting_account_id  = var.aws_skip_requesting_account_id
  skip_metadata_api_check     = true

  # Dynamic block: only injected if aws_minstack_endpoint has a value
  dynamic "endpoints" {
    for_each = var.aws_minstack_endpoint != "" ? [1] : []
    content {
      ec2   = var.aws_minstack_endpoint
      sts   = var.aws_minstack_endpoint
      iam   = var.aws_minstack_endpoint
      ecr   = var.aws_minstack_endpoint
      eks   = var.aws_minstack_endpoint
      s3    = var.aws_minstack_endpoint
      logs  = var.aws_minstack_endpoint
      cloudwatch = var.aws_minstack_endpoint
      cognitoidp = var.aws_minstack_endpoint
    }
  }
}
```

### How MiniStack Emulation Works

When `aws_minstack_endpoint = "http://localhost:4566"`, the `endpoints` block is injected into the provider and **all AWS services are redirected to MiniStack**:

| Service | Normal Behavior | MiniStack Behavior |
|---------|-----------------|---------------------|
| `ec2` | Calls real EC2 API | Calls `http://localhost:4566` |
| `eks` | Creates real EKS cluster | Creates an embedded **k3s cluster in Docker** |
| `ecr` | Creates repos in real ECR | Creates repos in MiniStack |
| `sts` | Validates credentials with STS | Bypassed (thanks to `skip_credentials_validation`) |
| `iam` | Creates real roles/policies | Creates roles/policies in MiniStack |

> **Two key flags:** `aws_skip_credentials_validation = true` and `aws_skip_requesting_account_id = true` prevent the provider from calling STS during `plan`/`apply`. This allows running `terraform plan` **without valid AWS credentials**, which is essential for local emulation.

## Modules

Terraform organizes infrastructure into **reusable modules** within `deploy/IaC/modules/`. Each module has its own `main.tf`, `variables.tf`, `outputs.tf`, and `versions.tf`.

### VPC — Virtual Network

> **Module:** `modules/vpc`

Creates the **isolated network** where everything deploys: VPC, public/private subnets, NAT Gateway, Internet Gateway, and VPC Flow Logs.

| Resource | Description |
|----------|-------------|
| **VPC** | Main network with CIDR `10.0.0.0/16` |
| **Public Subnets** | 3 AZs (`us-east-1a`, `us-east-1b`, `us-east-1c`) — load balancer lives here |
| **Private Subnets** | Where EKS nodes live |
| **NAT Gateway** | Allows Internet access from private subnets (~`$32.85/month` cost) |
| **Internet Gateway** | VPC connection to Internet |
| **VPC Flow Logs** | Network traffic auditing (optional, can be disabled locally) |

### ECR — Image Repository

> **Module:** `modules/ecr`

Creates **three ECR repositories** (one per project service) with lifecycle policy and vulnerability scanning:

| Repository | Image |
|-----------|-------|
| `softwarelearningguide-api` | ASP.NET Core REST API |
| `softwarelearningguide-outboxprocessor` | Outbox Processor Worker |
| `softwarelearningguide-consumer` | Consumer Worker |

### EKS — Kubernetes Cluster

> **Module:** `modules/eks`

Creates the **EKS cluster** where Helm charts are installed. Manages the control plane, managed node group, add-ons, Access Entries (for `kubectl`), and OIDC provider (for IRSA).

| Resource | Description |
|----------|-------------|
| **EKS Cluster** | Managed control plane (v1.31) |
| **Managed Node Group** | EC2 `t3.medium` nodes where pods run |
| **Add-ons** | `vpc-cni`, `kube-proxy`, `coredns` |
| **Access Entries** | IAM permissions for `kubectl` (no manual `aws-auth` editing) |
| **OIDC Provider** | Enables IRSA (IAM Roles for Service Accounts) |
| **Logging** | Control plane logging (api, audit, authenticator) |

## Variables and .tfvars Files

All configuration is parameterized through **variables** in `variables.tf`. Values are passed via `.tfvars` files.

### Key Variables

```hcl
variable "project_name" {
  description = "Project name; used as prefix for created resources."
  type        = string
  default     = "softwarelearningguide"
}

variable "aws_minstack_endpoint" {
  description = "If set (http://localhost:4566), ALL services point to MiniStack."
  type        = string
  default     = ""
}

variable "aws_skip_credentials_validation" {
  description = "Skip STS validation. Required for MiniStack and credential-less plans."
  type        = bool
  default     = true
}
```

The **EKS toggles** (`eks_create_managed_node_group`, `eks_create_addons`, `eks_create_oidc_provider`, etc.) are especially important because they disable EKS features that **MiniStack doesn't support**:

| Variable | Real AWS | MiniStack |
|----------|----------|-----------|
| `eks_create_managed_node_group` | `true` (creates EC2 nodes) | `false` (embedded k3s has its own node) |
| `eks_create_addons` | `true` (vpc-cni, coredns) | `false` (k3s includes its own add-ons) |
| `eks_create_access_entries` | `true` | `false` (k3s has its own access) |
| `eks_create_oidc_provider` | `true` (IRSA) | `false` (not used in local mode) |
| `enable_nat_gateway` | `true` | `false` (not needed locally) |
| `enable_vpc_flow_logs` | `true` | `false` (not used locally) |

### `terraform.tfvars.example` — Template for Real AWS

```hcl
project_name = "softwarelearningguide"
environment  = "dev"
region       = "us-east-1"
aws_skip_credentials_validation = true
aws_skip_requesting_account_id  = true
# ... (full config for real AWS deployment)
```

### `terraform.minstack.tfvars.example` — Template for MiniStack

```hcl
aws_access_key         = "test"
aws_secret_key         = "test"
aws_minstack_endpoint  = "http://localhost:4566"
aws_skip_credentials_validation = true
aws_skip_requesting_account_id  = true
enable_nat_gateway = false
enable_vpc_flow_logs = false
eks_enable_access_config      = false
eks_create_managed_node_group = false
eks_create_addons             = false
eks_create_access_entries     = false
eks_create_oidc_provider      = false
```

## Local Emulation Mode with MiniStack

> **This is the mode for practicing without touching real AWS.**

### How It Works

With `terraform.minstack.tfvars.example`, Terraform connects to MiniStack (`http://localhost:4566`) and:

1. **VPC**: MiniStack emulates EC2/VPC (since v1.4.9). Creates VPC and subnets.
2. **ECR**: Creates repositories in MiniStack. You can `docker push` to `localhost:4566`.
3. **EKS**: MiniStack creates a **real k3s cluster embedded in Docker**. The k3s cluster has its own node and networking components.

```
┌──────────────────────────────────────────────────────────┐
│  MINISTACK (Docker Container)                            │
│  ┌────────────────────────────────────────────────────┐  │
│  │  Port 4566                                         │  │
│  │  ├── /ecr   → Emulated ECR repositories            │  │
│  │  ├── /eks   → Embedded k3s cluster                 │  │
│  │  ├── /ec2   → Emulated VPC, subnets, NAT           │  │
│  │  └── /iam   → Emulated roles/policies              │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────┬───────────────────────────────┘
                           │ localhost:4566
                           ▼
┌──────────────────────────────────────────────────────────┐
│  TERRAFORM (your machine)                                │
│  terraform plan -var-file="terraform.minstack.tfvars"    │
│  terraform apply -var-file="terraform.minstack.tfvars"   │
└──────────────────────────────────────────────────────────┘
```

### Step-by-Step — Complete Emulated Workflow

```bash
# 1. Start MiniStack and Redis
docker-compose up -d ministack redis

# 2. Initialize Terraform (downloads providers)
cd deploy/IaC
terraform init

# 3. Verify syntax and format
terraform fmt -recursive
terraform validate

# 4. Plan against MiniStack (no real AWS touched)
terraform plan -var-file="terraform.minstack.tfvars.example"

# 5. Apply (creates VPC, ECR and EKS emulated in MiniStack)
terraform apply -var-file="terraform.minstack.tfvars.example"

# 6. Check created resources
terraform output ecr_repository_urls
terraform output eks_cluster_name

# 7. Teardown (destroys everything, including the k3s cluster)
terraform destroy -var-file="terraform.minstack.tfvars.example" -auto-approve
```

### Verifying Emulated Resources

```powershell
# View ECR repositories created
aws --endpoint-url http://localhost:4566 ecr describe-repositories

# View the emulated EKS cluster (k3s)
aws --endpoint-url http://localhost:4566 eks describe-cluster --name softwarelearningguide-dev-eks

# View the VPC created
aws --endpoint-url http://localhost:4566 ec2 describe-vpcs
```

## Real AWS Mode (Reference)

> **Only run this when you want to deploy for real. Infrastructure = cost.**

### Prerequisites

| Tool | Installation (Windows) |
|------|------------------------|
| AWS CLI | `winget install Amazon.AWSCLI` |
| Terraform | `winget install Hashicorp.Terraform` |
| AWS Credentials | `aws configure` |

### Step-by-Step — Real AWS

```bash
# 1. Create the variables file
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars: fill in admin_arns, region, sizes...

# 2. Initialize
terraform init

# 3. Plan (without creating anything yet)
terraform plan -var-file="terraform.tfvars"

# 4. Apply (creates VPC + EKS + ECR — ~10-15 min)
terraform apply -var-file="terraform.tfvars"

# 5. Get useful values
terraform output kubeconfig_command
terraform output ecr_repository_urls
```

### Scenario Reference

| Scenario | Var-file | Credentials | Result |
|----------|----------|-------------|--------|
| Quick plan (no changes) | `terraform.tfvars.example` | None | Proposed graph; doesn't contact AWS |
| Real AWS deployment | `terraform.tfvars` | `aws configure` | Real VPC + EKS + ECR (real cost) |
| Emulated with MiniStack | `terraform.minstack.tfvars` | `test`/`test` | VPC + ECR + k3s local on `localhost:4566` |

## Outputs — Output Values

The `outputs.tf` file defines **values that Terraform exposes** after `apply`. These are the data you need for subsequent steps:

| Output | Description | Use |
|--------|-------------|-----|
| `vpc_id` | ID of the created VPC | Reference for other resources |
| `public_subnet_ids` | Public subnets | Load balancing |
| `private_subnet_ids` | Private subnets | EKS nodes |
| `ecr_repository_names` | ECR repository names | Image references |
| `ecr_repository_urls` | Full ECR URLs | `docker tag/push` of images |
| `ecr_docker_tags` | Ready docker tag commands | Facilitates image pushing |
| `eks_cluster_name` | EKS cluster name | `kubectl` and `helm` |
| `eks_cluster_endpoint` | API server endpoint | kubectl configuration |
| `kubeconfig_command` | Command to get kubeconfig | `aws eks update-kubeconfig` |
| `eks_oidc_provider_arn` | OIDC provider ARN | IRSA |

```bash
# After terraform apply, get values
terraform output ecr_repository_urls
# → {"api": "123456789012.dkr.ecr.us-east-1.amazonaws.com/softwarelearningguide-api:latest", ...}

terraform output kubeconfig_command
# → aws eks --region us-east-1 update-kubeconfig --name softwarelearningguide-dev-eks --alias softwarelearningguide-dev-eks
```

## Workflow: Essential Commands

### Basic Terraform Commands

```bash
# Initialize (downloads providers and modules) — run ONCE
terraform init

# Format HCL code (canonical style)
terraform fmt -recursive

# Validate syntax and references (doesn't contact AWS)
terraform validate

# See the plan of changes (doesn't create anything)
terraform plan -var-file="terraform.tfvars"

# Apply changes
terraform apply -var-file="terraform.tfvars"

# Destroy all infrastructure
terraform destroy -var-file="terraform.tfvars" -auto-approve

# Show current state
terraform show

# Import existing resources into Terraform
terraform import aws_vpc.main vpc-12345678
```

### Typical Development Cycle

```bash
# Quick development cycle (against MiniStack)
terraform init                                  # Once
terraform fmt -recursive                        # Format
terraform validate                              # Validate syntax
terraform plan -var-file="terraform.minstack.tfvars.example"  # See plan
terraform apply -var-file="terraform.minstack.tfvars.example"  # Apply
# ... test with helm ...
terraform destroy -var-file="terraform.minstack.tfvars.example" -auto-approve  # Clean up
```

## Best Practices and Security

### Best Practices Applied

- **Local state in development**: `terraform.tfstate` stays on the local machine. For production, use a **remote backend** (S3 + DynamoDB) to avoid shared state issues.
- **`.terraform/` in `.gitignore`**: The `.terraform/` directory (where providers are downloaded) is gitignored. **The `.terraform.lock.hcl` should be committed** to pin exact provider versions.
- **Parameterized variables**: Everything is in `variables.tf` with sensible defaults. No "magic numbers" in HCL files.
- **Separate modules**: VPC, ECR, and EKS are independent modules. Each can be tested and versioned separately.
- **Skip credentials**: The `skip_credentials_validation` and `skip_requesting_account_id` flags allow `plan` without credentials, essential for CI/CD and local emulation.

### Security

- **Credentials outside the repo**: Real credentials never go in the code. Resolved from the environment (`~/.aws/credentials`) or IAM role.
- **MiniStack = dummy credentials**: `test`/`test` only works against MiniStack. Never use these credentials against real AWS.
- **Minimum privilege principle**: In production, `admin_arns` for EKS only grant necessary permissions.
- **No `force_delete` in production**: `ecr_force_delete = true` is the dev default. In production, set to `false` to prevent accidental deletion of repos with images.
